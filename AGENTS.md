# Project agent memory

**This repo's purpose: run nested sampling (PolyChord) over the parameter space of R2D2 and WSClean to find their failure modes.** Everything else (Docker images, smoke tests, pinned upstream revisions) exists to serve that. It is not a paper-reproduction or benchmarking harness.

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- `./ri` (the `ri` file at the repo root) is the front door and the only entrypoint users are pointed at: stdlib `argparse` that turns flags into the environment variables `scripts/lib/defaults.sh` already reads, then dispatches into `scripts/`. It holds no behaviour - new behaviour goes in a script, with a subcommand added in `ri` and a case in `scripts/test_cli.py`. `./ri --dry-run <command>` prints what it would run.
- Nested-sampling infrastructure, run commands, and the per-stage profiler (`./ri profile <run>`) are documented in `docs/nested-sampling.md`; use those entrypoints instead of ad hoc container wiring.
- The `polychord` and `meqtrees` images both bake in files from `scripts/lib/nested_sampling` at build time (no live mount); after editing those files, rebuild every image that copies them (`scripts/build.sh polychord`, `scripts/build.sh meqtrees`) before starting a nested-sampling run, or it silently runs the stale baked-in code. The exception is `r2d2_serve.py`, which the R2D2 sidecar runs off the repo bind mount, so it needs no rebuild. `polychord` copies the whole directory, `meqtrees` only the three simulate-side scripts (`simulate_point_source_ms.py`, `point_source_forest.py`, `ms_to_r2d2_mat.py`) - except that the `meqtrees` build also bind-mounts `common.py` and `defaults.toml` to bake the MS skeleton cache, so a parameter-space change (`[[parameter_space]]` in `defaults.toml`, the one authoritative copy) needs both images rebuilt.
- `scripts/build.sh` hashes each image's build inputs into an `ri.build-inputs` label and skips `docker build` when nothing changed (~0.08s), so rebuilding freely is cheap; the input list lives in `build.sh` and must be updated whenever a Dockerfile starts copying something new.
- Host `__pycache__` is excluded from both the context (root `.dockerignore`) and the build-input hash, so a `--self-check` does not force a rebuild.
- Image tags are shared across worktrees. Capture `docker images -q <tag>` per timing run and rebuild all images before trusting a result if another session could have rebuilt one.
- Memory, not CPU, caps a run: ~3.4GB per R2D2 rank (~0.2GB per WSClean rank), linear in `NS_MPI_PROCS` and independent of `NS_NLIVE`, so raise `--nlive` freely and size `--mpi-procs` to fit. `scripts/lib/rank-budget.sh` clamps and reserves against free memory. Sessions share this host, so expect another session's run to shrink yours - which is why `./ri health` with no argument reports *every* run that still has ranks, and why the default run directory is claimed with a bare `mkdir` (`ns_claim_run_dir` in `scripts/lib/run-config.sh`) rather than assumed: two searches started in the same second used to share one, and write each other's evaluations, FIFOs and `summary.json`. RSS hides the squeeze, because it excludes swap: `./ri health` reports what the kernel pushed out per run, and warns on a worker that is mostly on disk only while `/proc/pressure/memory` says something is waiting on those pages - being swapped out and being read back are different things, and the second is the one that costs evaluation time (and never fails). Sidecars a killed run left holding memory are removed by the next run before it sizes itself (`ns_reap_leaked_sidecars`), so `./ri health` naming them is a report, not a chore.
- A failed evaluation scores `FAILURE_OBJECTIVE`, which PolyChord maximizes - correct for the algorithm failing, wrong for a dead worker, so the two are kept apart (`WORKER_DIED` in `common.py`): a worker that dies, or goes silent past the reply timeouts next to it, is killed, retried, and then stops the run instead of being scored. MeqTrees deadlocking with its meqserver (roughly once in 2,000-5,000 evaluations) is caught before that, inside the worker: `PREDICT_WAIT_SECONDS` in `simulate_point_source_ms.py` bounds the predict Timba would otherwise wait on forever, and the worker replaces its own meqserver in ~0.2s rather than holding every rank in PolyChord's collective. An evaluation that hit one leaves a `meqserver-wedged.log`. Runs checkpoint, and `run_with_retries` in `scripts/lib/progress-bar.sh` restarts a run that died in place (`NS_RETRIES`, default 2) - but only while the failed attempt scored evaluations, so a deterministic failure stops at once (dead points are the wrong measure here: PolyChord's count is frozen between checkpoint writes, so it reads zero for a run that has been imaging for an hour). That budget counts failures that come straight back rather than restarts ever made - an attempt that ran `NS_RETRY_RESET_SECONDS` (1800) before dying hands it back, or a multi-day search that healed itself twice on day one is out of retries for the rest of the week. Each restart appends to the run's `restarts.log`, which `./ri health` reports. `run_with_retries` only sees a run that *exits*, so `_ns_stall_watchdog` (same file) covers the one that hangs instead - a rank stuck in an MPI collective burns every core forever with no status for anything to act on - by killing a run that finishes no evaluation in `NS_STALL_TIMEOUT` (7200s, `--stall-timeout`; well clear of `IMAGING_REPLY_TIMEOUT`'s 3600s single-evaluation ceiling, against a measured worst gap of 23.5s on a live R2D2 search). The kill is by command line (`ns_run_process_pattern`, shared with `./ri resume`'s liveness guard) because the pid the run script holds is the `docker exec` client and the ranks are children of `containerd-shim`. A restart adopts the previous attempt's evaluations unconditionally, never gated on PolyChord's `.resume` file - PolyChord writes that only at its first checkpoint, so gating it made a restart before then collide with its own eval directories, and because the likelihood is called from Fortran one rank's traceback hangs every other rank forever; anything unexpected in the likelihood therefore ends in `abort_run` (`MPI_Abort`) rather than a raise. A run with no `summary.json` stopped early: `./ri runs` lists those (the HTML report cannot - it globs for `summary.json`) and `./ri resume <run>` continues one from its own recorded `run.env`. A *live* run has no `summary.json` either, so both `./ri runs` and `./ri health` tell it apart by its processes, and `./ri resume` refuses one - a second job over the same checkpoint corrupts both. `./ri health` is the in-flight question instead - progressing, stalled, or scoring nothing but `FAILURE_OBJECTIVE`, which PolyChord maximizes, so a broken imager reads as a spectacular discovery. It also names sidecars a dead run left holding memory. Read-only and free to run against a live search; docs/nested-sampling.md, "Is the run healthy?". PolyChord rewrites `chains/` only every `nlive` dead points - two hours at a time on a 16-rank R2D2 search - so its dead-point count is frozen between writes and anything reporting progress from it must carry it forward across that interval from the evaluation directories (`dead_points_now`, `_ns_dead_now`); `stage` reports the raw count with its age precisely so nobody reads it as current. Why a run stopped is only ever in its `run.log`, which `run_with_progress` tees as the run goes - no other artifact records it.
- CI runs only what needs no Docker. The image-dependent self-checks (`--self-check` in each `scripts/lib/nested_sampling` module) run nowhere automatically: `./ri self-check` is the entry point, and it runs the working tree inside the images, so no rebuild is needed to check a change. `scripts/test_watchdogs.py` is the host-side half of the deadlock-watchdog checks and does run in CI. `./ri self-check self-heal` is the only check that starts a real search - it SIGKILLs one and SIGSTOPs a rank of another (the hang the retry loop cannot see) and asserts both recover, in ~90s on throwaway directories; every bug found in the retry machinery so far passed the fixtures and failed that kill. Shell self-checks run under `set -e`, which exempts a negated command - a `! cmd` assertion can never fail, so write negative assertions as `cmd && { echo "FAIL: ..."; exit 1; }`; CI's shellcheck now covers `scripts/lib/*.sh` (SC2251) and catches the mistake.
- Every image must byte-compile its interpreter's stdlib at build time. Check a new base image by counting its stdlib `.pyc` files.
- Benchmark direct stage timings before end-to-end A/B confirmation. Effects below 0.1s need at least 30 interleaved pairs; check host load and use `timeout` because MeqTrees can hang.
